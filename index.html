02  /  The core idea

Where does your data actually go?

Most AI products are a thin client: your keystrokes travel to a server you don’t control, get processed somewhere you can’t see, and come back as an answer. You are trusting a company, not a piece of software.

Vayris inverts the default. The agent loop, your documents, and its memory live on your machine. If you point it at a hosted model, that is a choice you make and can see in the source — not a round trip built into the product.

Model runtime is yours to pick: a local one, or a provider key you supply.
Either way the choice is visible in the source, not hidden in a client.

03  /  The philosophy

Your machine. Your data. Your control.

Local-first

The desktop app is the product — not a login screen in front of a service. It keeps working the way you left it.

Inspectable

Permissions, memory, the agent loop: all of it is source you can open, diff, and argue with.

Yours to change

Fork it, strip a module out, wire a different model in. Nothing here is a black box you rent.

04  /  Under the hood

Built to be inspected,
not just used.

Four modules, one loop.
Each one is a directory in the repo.
01

Agentic engine

The plan-act-observe loop that turns a request into steps, runs them, and reads the result before deciding what comes next.

core / loop
02

Retrieval & memory

A retrieval layer over the documents and context you give it, indexed locally so the agent can recall your work instead of guessing at it.

rag / index
03

Guardrails

A checking layer that sits between intent and action, so what the agent is about to do is reviewable before it happens.

safety / policy
04

Voice input

Speech-to-text wired into the same loop, for the times describing a task out loud is faster than typing it.

stt / input

Clone the repo and start it yourself. A few more minutes up front, and in exchange you can read every line that runs on your machine before it runs.

cd vayris
npm install && npm start
